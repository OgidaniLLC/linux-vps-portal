# MTSyncAll コピートレード ユーザーマニュアル

**対象EA:** MTS_CopyMaster / MTS_CopySlave v1.05 （MT5 / MT4）

---

## 1. 概要

MTSyncAll コピートレードは、超低遅延でMT5/MT4間のポジションをコピーするEAシステム。

- **マスターEA**: ポジションのopen/close/modifyを検知して配信
- **スレーブEA**: 受信して同じ操作を自分の口座で実行

### 主な特徴

- **超低遅延**: イベント駆動通知でマスターからスレーブへ即時配信（closeキュー方式により一括決済も20〜50ms）
- **3通信モード**: 同一PC（共有メモリ）/ 他PC（TCP）/ 両方（同時配信）
- **複数マスター対応**
- **複数スレーブ対応**: 1マスターに複数スレーブ接続可能（1対多）
  - ※ 1スレーブが複数マスターを同時購読することは不可（多対多運用不可）
- **プラットフォーム自由組合せ**: MT5↔MT5 / MT4↔MT4 / MT5↔MT4 / MT4↔MT5 すべて対応
- **部分決済対応**: マスターの部分決済を割合（lot_pct）でスレーブにも反映
- **冪等性保証**: 二重発注なし
- **自動クリーンアップ**: マスター不在ポジションを自動決済（HBで同期）
- **フェイルセーフ**: 鮮度・スプレッド・価格乖離・HBタイムアウトの4重ガード

## 2. インストール

### 配布物の構成

```
MTSyncAll-CopyTrade/
├── MQL5/
│   ├── Libraries/
│   │   └── MTSyncAll.dll          ← MT5用（64bit）
│   ├── Experts/
│   │   └── MTSyncAll/
│   │       ├── MTS_CopyMaster.ex5
│   │       └── MTS_CopySlave.ex5
│   └── Indicators/
│       └── MTSyncAll/
│           └── MTS_CopyMonitor.ex5   ← モニター（任意）
├── MQL4/
│   ├── Libraries/
│   │   └── MTSyncAll32.dll        ← MT4用（32bit）
│   ├── Experts/
│   │   └── MTSyncAll/
│   │       ├── MTS_CopyMaster.ex4
│   │       └── MTS_CopySlave.ex4
│   └── Indicators/
│       └── MTSyncAll/
│           └── MTS_CopyMonitor.ex4   ← モニター（任意）
├── USER_MANUAL.md       ← 本マニュアル（コピートレード本体: Master/Slave）
└── MONITOR_MANUAL.md    ← モニター（MTS_CopyMonitor）専用マニュアル
```

### 配置手順

MT5/MT4の**データフォルダ**（**ファイル → データフォルダを開く**）を開き、配布物の `MQL5/` または `MQL4/` フォルダをそのままコピー。**リネーム不要**。

> ✅ MT5用は `MTSyncAll.dll`、MT4用は `MTSyncAll32.dll` とファイル名で識別済み。
> MT5/MT4が同じデータフォルダを共有する構成でも安全に共存できます。

> ℹ️ `Indicators/MTSyncAll/MTS_CopyMonitor`（モニター）はスレーブ側の状態を可視化する**任意**のインジケーターです。導入・使い方は同梱の **MONITOR_MANUAL.md** を参照してください。

## 3. 通信モード

### 3.1 同一PC（共有メモリ）

```
[MT端末A]              [MT端末B]
MTS_CopyMaster   →     MTS_CopySlave
   (超低遅延イベント駆動)
```

- マスター: `通信方式 = 同一PC（共有メモリ）`
- スレーブ: `通信方式 = 同一PC（共有メモリ）`
- 別ブローカーの端末（XM ⇔ TITAN等）でもOK

### 3.2 他PC（TCP / LAN・WAN経由）

```
[マスターPC]                    [スレーブPC]
MTS_CopyMaster (TCPサーバー) → MTS_CopySlave (TCPクライアント)
```

- マスター: `通信方式 = 他PC（TCP）`、`リッスンポート = 14785`
- スレーブ: `通信方式 = 他PC（TCP）`、`接続先ホスト = "192.168.x.x"`、`接続先ポート = 14785`

> ⚠️ **他PC接続にはネットワーク設定の専門知識が必要です。**
>
> **家庭内LAN（同一ルーター配下）の場合:**
> - マスターPCの**Windowsファイアウォール**で `MTSyncAll.dll` 経由のTCPポート（14785等）の受信を許可
> - マスターPCの**ローカルIP**（例: 192.168.1.10）をスレーブの`接続先ホスト`に指定
> - ローカルIPはコマンドプロンプトで `ipconfig` で確認可能
> - DHCPでIPが変わる場合はマスターPCに**固定IP**を割り当てるか、ルーターのDHCP予約機能を使用
>
> **インターネット越し（WAN経由）の場合:**
> - マスターPC側ルーターで**ポートフォワーディング**設定が必要
> - マスター側のグローバルIPは**動的IP**（プロバイダ）の場合、DDNSサービス併用を検討
> - **セキュリティリスク**：TCPポートを公開するとインターネット上の任意の端末から接続試行が可能
>   → VPN（WireGuard、Tailscale等）越しの接続を強く推奨
>
> **VPS環境の場合:**
> - VPSプロバイダのファイアウォール（セキュリティグループ等）でポート開放が必要
> - クラウド事業者によっては追加ネットワーク設定が必要
>
> ネットワーク設定（ファイアウォール・ポート開放・ルーティング）に不慣れな方は、
> **同一PC（共有メモリ）モードの使用を推奨します。**

### 3.3 両方（同時配信）

```
[マスターPC]
MTS_CopyMaster (両方)
   ├─ 同一PCのスレーブへ共有メモリ配信
   └─ 他PCのスレーブへTCP配信
```

- マスター: `通信方式 = 両方（同一PC＋他PC）`
- 同一PC内のスレーブと、別PCのスレーブを同時に配信できる
- スレーブ側は `同一PC` または `他PC` を選択

## 4. パラメータ仕様

### 4.1 マスター（MTS_CopyMaster）

#### ========== 【基本】==========

| パラメータ | デフォルト | 説明 |
|---|---|---|
| ├ マスターID | マスター 1 | マスターID（1〜13） |
| ├ 通信方式 | 同一PC（共有メモリ） | 同一PC / 他PC（TCP）/ 両方 |
| │└ リッスンポート | 14785 | TCPリッスンポート（他PC・両方のみ） |
| └ 配信対象magic | 0 | 0=全magic配信 |

#### ========== 【詳細】==========

| パラメータ | デフォルト | 説明 |
|---|---|---|
| ├ サフィックス手動指定 | "" | 通常は空のまま。ブローカーの全銘柄に同じ接尾辞がある場合だけ手動指定する |
| ├ HB送信間隔(ms) | 5000 | ハートビート送信間隔 |
| ├ バックアップポーリング間隔(ms) | 1000 | イベント取りこぼし保険 |
| └ ログレベル | 通常ログ | ログなし(最速)/通常ログ |

> **サフィックスの動作**
> - **空（デフォルト）**: チャートシンボルの先頭6文字からFX通貨ペアを自動検出し、残りをサフィックスとして全シンボルに適用
> - **手動指定**: 指定したサフィックスで終わるシンボルのみ配信。それ以外はスキップ
> - **非FXシンボルや名称違い**: `XAUUSD+ -> GOLD` のように名前自体が違う場合は、スレーブ側の `個別シンボルマッピング` で対応する

### 4.2 スレーブ（MTS_CopySlave）

#### ========== 【基本】==========

| パラメータ | デフォルト | 説明 |
|---|---|---|
| ├ マスターID | マスター 1 | 購読するマスターID（マスター側と一致させる） |
| ├ 通信方式 | 同一PC（共有メモリ） | 同一PC / 他PC（TCP） |
| │├ 接続先ホスト | "127.0.0.1" | TCP接続先IP（他PCのみ） |
| │└ 接続先ポート | 14785 | TCP接続先ポート（他PCのみ） |
| ├ ロット指定方式 | 倍率 | 倍率 / 固定ロット |
| ├ ロット倍率 | 1.0 | マスター0.1×倍率2.0=スレーブ0.2（倍率モード時） |
| ├ 固定ロット | 0.01 | 常にこのロットでコピー（固定モード時） |
| ├ スレーブmagic | 99000001（MT5）/ 99000002（MT4） | スレーブ独自magic（他EAとの衝突回避のため8桁デフォルト） |
| ├ シンボルサフィックス | "" | **原則空のまま。** 空ならスレーブのチャートシンボルから接尾辞を自動検出するので、マスター側に接尾辞が無くてもスレーブ側に接尾辞があれば自動で付与される。手動指定は自動検出を上書きするため、実際の接尾辞とズレるとSKIPされる（後述の注記を参照） |
| └ 個別シンボルマッピング | "" | カンマ区切りの文字列。例: "EURUSD=EURUSDpro,GBPUSD=GBPUSD.x,XAUUSD=GOLD" |

> **⚠️ スレーブの `シンボルサフィックス` は原則「空」にすること**
>
> 空にすると、スレーブEAをアタッチしている**チャートのシンボル名**から接尾辞を自動検出する（`EURUSD.a` → `.a`、`GOLDm` → `m` 等）。
> マスターが接尾辞なし（`XAUUSD`）を配信し、スレーブ側に接尾辞がある（`XAUUSD.a`）構成でも、**スレーブを空にしておけば自動で `.a` を付けてコピー**する。**スレーブ側に手動でサフィックスを設定する必要はない。**
>
> 手動指定すると自動検出を上書きするため、入力値が実際の接尾辞とズレたり二重付与になると存在しないシンボル名になり、取引がSKIPされる。
>
> **手動指定が要るのは次の場合だけ:**
> - スレーブEAをコピー対象とは別サフィックスの銘柄チャート（例: 24時間稼働用に `BTCUSD` チャート）にアタッチしていて、コピー対象（例: `EURUSD.pro`）の接尾辞をチャートから自動検出できない
> - 非FXシンボルで、接尾辞を外した base 名（例: `GOLD`）がスレーブの気配値に単独で存在せず自動逆算できない
>
> 接尾辞ではなく**名前自体が違う**場合（`XAUUSD` → `GOLD` 等）は、サフィックスではなく `個別シンボルマッピング` を使う。

#### ========== 【詳細】==========

| パラメータ | デフォルト | 説明 |
|---|---|---|
| ├ シグナル有効期限(ms) | 10000 | 0=無効 |
| ├ 最大スプレッド% | 0.20 | FX主要通貨は0.10程度でも可 |
| ├ 最大価格乖離% | 0.10 | 価格乖離ガードON時のみ。不利方向のみ判定。0=不利方向のズレを許容しない |
| ├ 価格乖離ガードを使う | true | falseにすると最大価格乖離%を無視して、価格ズレでは保留しない |
| ├ 許容スリッページ% | 0.05 | OrderSendのdeviation変換 |
| ├ 最小有利価格差 | -1.0 | -1=無効、0=同値以上、0より大きい値=指定価格差以上有利な時だけコピー |
| ├ SL/TP設定方針 | 両方（推奨） | 相対距離コピー / close通知追随 / 両方 |
| ├ OrderSend失敗時リトライ回数 | 3 | |
| ├ リトライ間隔(ms) | 200 | |
| ├ HB途絶アラート閾値(秒) | 30 | |
| ├ HB途絶時動作 | アラートのみ | アラートのみ / 新規発注を停止 / スレーブ全決済 |
| ├ チケット永続化ファイル | "slave_tickets.csv" | 処理済みticket記録 |
| ├ バックアップポーリング間隔(ms) | 50 | イベント取りこぼし保険 |
| ├ ガードレール失敗時リトライタイムアウト(ms) | 10000 | スプレッド/価格乖離NG時のペンディング最大保持時間。-1=時間では破棄せず、マスターticketがHBから消えるまで保持 |
| └ ログレベル | 通常ログ | ログなし(最速)/通常ログ。ログなしでは監視用JSONLも出力しない（ticket CSVは維持） |

## 5. 銘柄別の推奨パラメータ

スプレッド・価格乖離は銘柄により大きく異なる。デフォルトは**FX主要通貨ペア**向け。

### 5.1 推奨スプレッド%

| 銘柄 | 通常スプレッド% | 推奨 `最大スプレッド%` |
|---|---|---|
| EURUSD / USDJPY / GBPUSD | 0.01〜0.02% | **0.20**（デフォルト）で問題なし |
| XAUUSD（ゴールド） | 0.01〜0.02% | **0.20**（デフォルト）で問題なし |
| **BTCUSD（仮想通貨）** | **0.05〜0.10%** | **0.20**（デフォルト）でOK |

> デフォルト（0.20%）はBTCUSD等の広スプレッド銘柄を考慮した値。FX主要通貨ペアのみ運用する場合は0.10程度に下げても良い。

### 5.2 推奨価格乖離%

| 用途 | 推奨設定 |
|---|---|
| スキャルピングを厳密コピー | `価格乖離ガードを使う=true`、`最大価格乖離%=0`、`最小有利価格差=-1` |
| スキャルピングを有利価格だけコピー | `価格乖離ガードを使う=true`、`最大価格乖離%=0`、`最小有利価格差=0.05〜0.10` |
| 同一PC・同一ブローカー | `価格乖離ガードを使う=true`、`最大価格乖離%=0.01〜0.05` |
| 別ブローカー（XM ⇔ TITANなど） | `価格乖離ガードを使う=true`、`最大価格乖離%=0.05〜0.10` |
| スイング/多少のズレを許容 | `価格乖離ガードを使う=false`、または `最大価格乖離%` を広げる |
| 別PC・WAN経由 | `価格乖離ガードを使う=true`、`最大価格乖離%=0.10〜0.20` |

> `最大価格乖離%` は大きくするほど緩く、小さくするほど厳しい。0は「不利方向のズレを許容しない」設定。
> 無効化したい場合は数値を極端に大きくするのではなく、`価格乖離ガードを使う=false` を使う。

### 5.3 用途別の設定例

#### XAUUSDスキャルピングコピー（遅延・不利約定を抑える）

```text
価格乖離ガードを使う = true
最大価格乖離% = 0
最小有利価格差 = -1
ガードレール失敗時リトライタイムアウト(ms) = -1
ログレベル = ログなし
```

マスターがポジションを持っている間は、不利価格なら保留し、有利または同値になったらコピーする。マスターticketがHBから消えたら保留も破棄する。

#### スイングコピー（取り逃しを減らす）

```text
価格乖離ガードを使う = false
ガードレール失敗時リトライタイムアウト(ms) = 10000
ログレベル = 通常ログ
```

価格ズレよりコピー成立を優先する。スキャルピングよりもポジション時間が長い運用向き。

## 6. 動作仕様

### 6.1 シグナル種別

| 種別 | タイミング | スレーブの処理 |
|---|---|---|
| `open` | マスター新規ポジション約定時 | 4ガードレール通過後にOrderSend |
| `close` | マスター決済時（部分決済含む） | 対応スレーブポジションを決済（部分決済はlot_pct=0.0〜1.0の割合でスレーブ側ロットの同比率を決済） |
| `modify` | マスターSL/TP変更時 | スレーブのSL/TPを相対距離で更新 |
| `hb` | 5秒ごと | 死活監視＋孤立ポジション自動クリーンアップ |

### 6.2 ガードレール（openのみ適用）

| 順序 | チェック | NG条件 | NG時の動作 |
|---|---|---|---|
| ① | 鮮度×価格複合判定 | 古い AND 不利価格 | **ペンディング（リトライ）** |
| ② | 冪等性 | 既に処理済みticket | スキップ（即破棄） |
| ③ | スプレッドフィルター | spread/price > `最大スプレッド%` | **ペンディング（リトライ）** |
| ④ | 価格乖離フィルター | `価格乖離ガードを使う=true` かつ 不利方向の乖離 > `最大価格乖離%` | **ペンディング（リトライ）** |

> ✅ 古いシグナルでも**有利価格なら発注**する設計
>
> ✅ ①③④は即破棄せず**ペンディングキューで保持**し、OnTimer毎に再チェック。
> スプレッド拡大やフラッシュクラッシュが解消されれば自動的に発注される。
>
> ✅ `ガードレール失敗時リトライタイムアウト(ms)` が0以上なら、その時間を超えた保留は破棄する。-1なら時間では破棄せず、マスターticketがHBから消えるまで保持する。
>
> ✅ `シグナル有効期限(ms)` は「受信したopenシグナルが古いか」を見る設定。`ガードレール失敗時リトライタイムアウト(ms)` は「一度保留に入ったシグナルを何ms待つか」を見る設定。

### 6.3 SL/TP設定方針

| 設定 | 動作 |
|---|---|
| **相対距離コピー** | マスターのSL/TP距離をスレーブの約定価格に適用してRR比を維持 |
| **close通知追随** | マスターのclose通知でスレーブも決済 |
| **両方（推奨）** | 上記両方を併用 — 通信途絶時は相対距離が保険、正常時は追随 |

> SL/TPがブローカー最小ストップレベル未満になる場合は自動切り上げ＋ログ。
> SL切り上げはリスク拡大を伴う点に注意。

### 6.4 HB途絶時の動作

| 設定 | 動作 |
|---|---|
| **アラートのみ** | 警告のみ表示 |
| **新規発注を停止** | 既存ポジションは保持、新規エントリーをブロック |
| **スレーブ全決済** | スレーブの全ポジションを即決済 |

### 6.5 孤立ポジション自動決済（HBクリーンアップ）

マスターはHB送信時に**現在保有ticketの一覧**を含めて配信。
スレーブはHB受信時、`g_tickets`マッピングのうち**マスター不在のticket**を検知して対応スレーブポジションを自動決済。

例：
- マスターでポジション手動決済（EAなしで決済） → 次回HBで検知 → スレーブも決済
- マスター再起動中の決済 → 起動後の最初のHBで検知 → スレーブも決済

### 6.6 チケット永続化（再起動対応）

スレーブEAは「マスターticket → スレーブticket」のマッピングをファイルに保存し、EA再起動時に復元する。

#### 目的

- スレーブEA再起動後も、マスターのclose/modify通知に正しく対応できる
- 二重発注防止（ガードレール②冪等性）が再起動を跨いで機能する

#### ファイル仕様

| 項目 | 内容 |
|---|---|
| パラメータ | `チケット永続化ファイル`（デフォルト: `slave_tickets.csv`） |
| 配置場所 | データフォルダの `MQL5/Files/Common/` または `MQL4/Files/Common/`（共通フォルダ） |
| 形式 | CSV（マスターticket, スレーブticket, 記録日時） |

#### 注意

- ファイルが破損した場合は手動で削除してEAを再起動（マッピング情報は失われる）
- 古いマッピング（既に決済済みのポジション）が残っていても、`open`通知は新規ticketで届くので問題なし
- 複数のスレーブEAを動かす場合は**ファイル名を別にする**こと（例: `slave_tickets_M1.csv`、`slave_tickets_M2.csv`）

### 6.7 シンボルマッピング

マスターとスレーブで使用するブローカーが異なり、シンボル名が違う場合に変換ルールを指定する。

#### パターン1: サフィックスで一括変換（必要な場合のみ）

すべてのシンボルに同じ接尾辞が付いている場合：

- 設定例: `シンボルサフィックス = "pro"`
- 動作: マスター "EURUSD" → スレーブ "EURUSDpro"
- 動作: マスター "GBPUSD" → スレーブ "GBPUSDpro"

接尾辞がないブローカーでは空のままにする。

#### パターン2: 個別マッピング

シンボルごとに名前が違う場合：

- 設定: `個別シンボルマッピング = "EURUSD=EURUSDpro,GBPUSD=GBPUSDpro,XAUUSD=GOLD"`
- 動作: マスター "EURUSD" → スレーブ "EURUSDpro"
- 動作: マスター "XAUUSD" → スレーブ "GOLD"

これはファイルを指定する項目ではない。EAパラメータ欄へ `マスターシンボル=スレーブシンボル` をカンマ区切りで直接入力する。

#### 優先順位

1. 個別マッピングに記載があればそれを優先
2. 個別マッピングになければサフィックスを適用
3. 両方未設定ならマスターと同じシンボル名をそのまま使用

#### 注意

- マッピング先のシンボルがスレーブブローカーで取引可能でないと発注失敗
- 必ずスレーブの**気配値表示**にマッピング先シンボルを追加してから運用すること

## 7. トラブルシューティング

### スレーブが受信しない

1. マスター・スレーブで `マスターID` が一致しているか確認
2. マスター側Expertsログで `[CopyMaster] OPEN ticket=...` が出ているか確認
3. スレーブ側Expertsログで `[CopySlave] v1.04 ... mode=...` の起動ログが出ているか確認
4. DLL差し替え時はMT再起動（実行中はファイルロック）

### コピーされるがSKIPされる

スレーブのExpertsログに `[Slave] SKIP Guardrail X (...)` が出ているはず：

| ガードレール | 対処 |
|---|---|
| Guardrail 1 (Age+Price) | 古い かつ 不利価格 → ペンディングに入る。`シグナル有効期限`を延長、または `ガードレール失敗時リトライタイムアウト(ms)` を調整 |
| Guardrail 3 (Spread) | スプレッド超過 → `最大スプレッド%`を引き上げ（BTCUSDは0.20） |
| Guardrail 4 (Deviation) | 価格乖離 → スキャルピングなら `最大価格乖離%=0` のまま保留。有効化しすぎる場合は `最大価格乖離%`を引き上げ、スイングなら `価格乖離ガードを使う=false` |
| Guardrail 5 (MinFavorable) | 最小有利価格差 → `最小有利価格差>=0` の時、指定価格差以上有利になるまで保留 |

### スレーブにポジションが残る

マスターHB送信時（5秒ごと）に自動決済される。
それでも残る場合はスレーブEAを再アタッチ。

### MT5/MT4 クラッシュ

- DLL差し替え時はMT5/MT4を**完全終了してから**実施
- DLL読込中は差し替え不可（ファイルロック）

### `unresolved import function call` エラー

- DLLとEAの定義が不一致 → DLLを最新に差し替え＋EA再コンパイル
- MT5は64bit、MT4は32bit のDLL混在不可

## 8. 利用期限

スレーブEAにはビルド日時から **90日間** の利用期限が設定されています。

- 期限はEAのプロパティ画面（共通タブ）の説明欄に表示されます
- 期限超過後は起動時に警告アラートを表示し、動作を停止します（INIT_FAILED）
- 期限を延長するには最新版のEAに差し替えてください

## 9. 既知の制限



- **同一MasterIDの重複起動は禁止**: 同じMasterIDのマスターEAを複数のチャートにアタッチすると2台目はINIT_FAILEDで停止します。複数マスターを使う場合はMasterIDを別々に設定してください。
- **マスター上限13台**
- **マスター保有ポジション数 約5,000件**（通常運用では問題にならない）
- **1スレーブが購読できるマスターは1台のみ**（多対多不可。複数マスターをコピーしたい場合はスレーブEAを複数アタッチ）
- **MT4スレーブのチャートは24時間取引銘柄を推奨**
  MT4は閉場銘柄のチャートではOnTimer/OnTickが停止し、コピー受信が止まる仕様。
  土日や閉場時間帯も継続稼働させる場合は、**BTCUSD等の24時間取引銘柄のチャート**にスレーブEAをアタッチすること。
  （マスター発注対象とチャート銘柄は別でOK。チャートはあくまで「EA動作のため」）

## 9. 用語集

| 用語 | 英語 | 説明 |
|---|---|---|
| **HB** | Heartbeat | マスターからスレーブへ定期送信する死活確認信号。5秒間隔。HBが途絶えたらマスター異常と判定 |
| **OrderSend** | - | MT5/MT4の発注関数。スレーブが受信したシグナルに従いブローカーへ発注する |
| **冪等性** | Idempotency | 同じ操作を複数回実行しても結果が変わらない性質。本システムでは同一ticketの二重発注を防止 |
| **ガードレール** | Guardrail | 発注前の安全チェック群。鮮度・冪等性・スプレッド・価格乖離の4種 |
| **ticket** | - | MT5/MT4の取引識別番号。マスターticket→スレーブticketのマッピングで紐付け管理 |
| **slot** | - | 共有メモリ上のデータ保存区画。マスターIDごとに4スロット使用（open/close/modify/hb） |
| **magic** | Magic Number | EAが自身の取引を識別するための番号。マスターとスレーブで別magicを使用 |
| **STOPS_LEVEL** | - | ブローカー固有の最小ストップレベル。SL/TPはこれ以上現在価格から離す必要がある |
| **FREEZE_LEVEL** | - | ブローカー固有のフリーズレベル。現在価格からこの距離以内のSL/TPは変更・決済不可 |
| **lot_pct** | - | 部分決済割合（0.0〜1.0）。マスター50%決済の場合 lot_pct=0.5 |
| **Pct** | Percentage | 百分率（%）表記。例：0.10 = 0.1% |
